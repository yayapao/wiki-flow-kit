# mylife：从事件进入个人理解

## 入口与归属

用户明确提出个人记录、访谈、思考整理或评价意图时进入本流程，例如“这个项目值得留下，采访我”“把这次选择整理到 mylife”。日常导入、项目资料整理和状态检查保持原有流程。例子用于说明意图，不限定为项目、求职或固定问卷。

`wiki-flow mylife` 只读返回已登记 Vault 与角色入口；`wiki-flow mylife interview`、`wiki-flow mylife observe` 返回当前角色指令。由当前会话模型阅读并执行，人设不会自行启动后台 Agent，也不需要 LLM Wiki API。初次进入时读取返回的 `vaultRules`、`entry` 和相关原页。未登记时仅询问目标 Vault，不猜路径或初始化已有库。

个人路径来自 `~/.config/wiki-flow/registry.json` 的 `personal.path`，入口默认 `首页.md`。它是独立 Obsidian Vault，文件域名 `mylife`，不注册为 aiwiki 项目，不更换 LLM Wiki 的 general 项目。

| 内容 | 归属 |
| --- | --- |
| 项目当前事实与规范 | 原 aiwiki 项目；LLM Wiki 中的快照仍是来源材料 |
| 外部原文与通用知识 | 原 valut |
| 用户如何理解、选择、解决问题及设想未来 | mylife |
| 采访者、旁观者的可移植指令 | 本 Skill 的 `personas/`；Vault 保存个人正文 |

## 协作方式

1. **理解想留下的东西。** 复用会话中已有材料；需要补充证据时，先查指定来源，项目规范遵守 aiwiki 的 AGENTS 和项目入口。明确用户关注的是一段经历、一个判断、一个点子，还是对未来的想象。
2. **按需交谈。** 有材料但缺少个人视角时使用[采访者](../personas/interviewer.md)。如果用户已经给出完整表达，直接协助整理；不为了走流程重复访谈。明确要求独立评价时切换[旁观者](../personas/observer.md)，说明已切换角色。
3. **沉淀到事件或主题。** 一段经历通常有背景、用户的判断和取舍、个人行动、结果、当下理解；按材料自然组织，无须填满每个栏目。保留用户自己的表达，把资料事实、用户陈述和未核实处区分开。以来源链接支持证据，不复制整套项目文档。
4. **继续生长。** 后续补充同一事件时合并原页；新思考、点子、想象通过双链关联原事件。形成简历条目或工作亮点时，放在对应工作项目内，并链接经历依据。只有用户想推进到“我”或明确调用旁观者时，才进行跨事件画像整理。

对话没有固定轮数。一轮通常追问 1～2 个关键问题，顺着回答深入。用户已授权沉淀，信息足以写清所选部分时直接保存并返回链接；事实不完整时可以保存已知内容与待补问题，标为“待补充”。不把每次保存变成审批，也不因必须填齐模板而拖延。用户说“只聊”“暂不保存”时保持对话，不写个人正文。

换话题或中断后，从对应事件原页及其“待继续的问题”恢复；不要求用户重讲，不为每次对话建立日记、回顾或反馈队列。

## 目录与写法

- `点子和灵感/`、`思考/`、`经历/`、`想象/`、`我/`、`附件/`、`模板/` 为稳定入口；不自动引入收件箱、日记、回顾、反馈等时间或流转目录。
- 经历按 `炒股/工作/生活/婚姻/家庭` 归属；工作项目默认 `经历/工作/项目/<事件标题>.md`。同一项目形成多个独立事件时，再按项目建子目录。尊重用户已有分类，避免每次访谈都建新目录。
- “我”的自述来自用户表达；`我/旁观者/` 允许独立推断，按人设标明证据、反例与不确定性，观察不能悄悄变成用户自述。
- 使用 Markdown、Vault 内 `[[目录/笔记]]` 与 `![[附件/文件]]`；YAML 属性中的双链需加引号。跨 Vault 用绝对文件路径或编码后的 Obsidian URI，普通双链不跨库。
- 属性保持扁平，按需要使用 `type`、`status`、`writing`、`event_date`、`related`、`sources`；`writing: 本人与LLM共同整理` 说明表达方式，不表示个人判断由模型发明。事件日期未知可留空，创建日期不能冒充发生日期。
- 首次使用相关类型时读取 Vault 对应模板。模板是提示，允许省略无内容的栏目，不在正文填入虚构示例、推测动机或成果数字。

## 保存与检查

```bash
wiki-flow find '事件关键词' --domain mylife
wiki-flow read '经历/工作/项目/事件标题.md' --domain mylife
wiki-flow write '经历/工作/项目/事件标题.md' --domain mylife --file <UTF-8临时正文> --expected <读取时sha256或new>
wiki-flow check --domain mylife
```

命令示例中的路径是结构说明，执行时替换为真实目标。新页先查重，旧页先读取基准；并发变化后重读合并。保存后回读，按需增量维护相应分类索引，首页只保留有价值的入口，不追加逐次更新日志。库内双链与附件用本地检查验证。

mylife 写入走本地原子替换和历史收据，不要求应用队列空闲，也不会调用 API 自动整理。只有注册表已将 mylife 纳入检索且本轮需要更新检索时才刷新相应索引；正文已保存与已建索引分别报告。当前迁移包仅覆盖 aiwiki、valut，不能声称已经备份个人 Vault。

## 反馈到 LLM Wiki

用户说“把这点也补回项目知识库”等明确提出反馈意图时，选取指定内容回到原流程：事实补充附证据并原位维护 aiwiki，个人判断作为有归属的用户观点，通用方法按适用范围整理到 valut。需要更新应用快照时复用已有导入流程。mylife 的事件页可记录反馈目标链接和实际处理结果；不新建反馈目录，不整库回传，也不把旁观者推断回写为项目事实。
